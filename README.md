# math-rpg

수학 선생 친구를 위한 슬더슬 같은 수학게임

수학 문제를 풀어 몬스터와 싸우는 스마트폰용 웹 게임입니다. 지금은 **전투 한 판이 돌아가는 시제품** 단계입니다.

이 문서는 사용설명서처럼 위에서부터 순서대로 따라 하면 되도록 썼습니다.

## 1. 지금 되는 것과 아직 없는 것

| 되는 것 | 아직 없는 것 |
| --- | --- |
| 전투 (기본 공격, 스킬, 방어, 필살기) | 갈림길 지도 |
| 삼각비 문제 33개 (数学I 기준) | 강화 고르기, 상점 |
| 일본어·한국어·영어 전환 | 도감 화면 |
| 몬스터 3종과 움직임 | 튜토리얼 |
| 기기 자동 저장 (언어, 승리 수, 유형별 정답 기록) | 오프라인 동작, 보스전 |

## 2. 실행해 보기

파일을 더블클릭해서 열면 동작하지 않습니다. 브라우저가 보안상 데이터 파일을 읽지 못하게 막기 때문입니다. 아래 둘 중 하나로 실행합니다.

**내 컴퓨터에서**

1. 이 폴더에서 터미널을 엽니다.
2. `python -m http.server 8000` 을 실행합니다. (VS Code의 Live Server 확장도 됩니다.)
3. 브라우저에서 `http://localhost:8000` 을 엽니다.

**스마트폰에서 (GitHub Pages)**

1. 저장소의 Settings → Pages 로 갑니다.
2. Source 를 "Deploy from a branch" 로, 브랜치를 `main` / `(root)` 로 정합니다.
3. 잠시 뒤 `https://<계정>.github.io/math-rpg/` 로 접속합니다.

`main` 에 아직 게임이 없을 때 폰으로 확인하려면 브랜치를 잠시 `dev` 로 바꿔서 봅니다.

## 3. 게임 방법

1. 적의 "다음 턴 예고"를 봅니다.
2. 행동을 고릅니다.
   - **기본 공격**: 쉬운 문제가 나옵니다. 맞히면 약한 피해를 줍니다.
   - **스킬**: 어려운 문제가 나옵니다. 맞히면 큰 피해를 줍니다.
   - **방어**: 쉬운 문제가 나옵니다. 맞히면 피해를 받지 않고 반격합니다. 틀리면 피해를 절반 받습니다. 연속으로는 쓸 수 없습니다.
3. 문제가 나오면 답을 고릅니다. 시간 제한은 없습니다.
4. 틀리면 공격이 빗나가고 해설이 나옵니다.
5. 3문제를 연속으로 맞히면 필살기를 쓸 수 있습니다. 틀리면 게이지가 0이 됩니다.
6. 적의 약점 유형 문제를 맞히면 피해가 1.5배입니다.

## 5. 문제 추가하는 법

문제는 `data/units/<단원>.json` 에 있습니다. **문장 틀**과 **숫자 묶음**으로 나뉘어 있어서, 숫자만 다른 문제는 한 줄만 추가하면 3개 언어로 모두 나옵니다.

**숫자만 다른 문제 추가**

해당 틀의 `items` 에 한 줄을 더합니다.

```json
{ "d": 20, "deg": 45, "answer": "20 m", "wrong": ["10√2 m", "22 m", "10 m"] }
```

- `answer`: 정답
- `wrong`: 오답 보기 3개. 정답과 겹치면 안 됩니다.
- 나머지(`d`, `deg` 등): 문장 틀의 `{d}`, `{deg}` 자리에 들어갈 값

**새로운 종류의 문제 추가**

`templates` 에 틀을 하나 더합니다.

| 항목 | 뜻 |
| --- | --- |
| `id` | 틀의 이름 (영문, 겹치지 않게) |
| `level` | 1 = 개념 확인, 2 = 계산, 3 = 응용 |
| `type` | 유형. 파일 위쪽 `types` 에 있는 이름이어야 합니다 |
| `text` | 문제 문장. ja, ko, en 세 가지를 모두 씁니다 |
| `explain` | 틀렸을 때 보여줄 해설 한 줄 |
| `items` | 숫자 묶음 목록 |

## 6. 숫자 조정하는 법

체력, 피해량 같은 값은 모두 `js/config.js` 한 파일에 있습니다. 각 줄 옆에 뜻이 적혀 있습니다. 몬스터별 체력과 약점은 `data/monsters.json` 에 있습니다.

지금 값은 모두 임시입니다. 직접 해 보고 고칩니다.

## 7. 화면 문구 고치는 법

버튼, 안내 문장은 `lang/ja.json`, `lang/ko.json`, `lang/en.json` 에 있습니다. 세 파일은 같은 항목을 가져야 합니다. 한 파일에 항목을 추가하면 나머지 두 파일에도 추가합니다.

## 8. 몬스터 추가하는 법

1. `data/monsters.json` 에 항목을 추가합니다. (`id`, 이름, 체력, 약점 유형)
2. `js/stage.js` 에 그리는 함수를 하나 만들고 `FOE_DRAW` 에 같은 `id` 로 등록합니다.

그림은 이미지 파일 없이 원, 다각형, 선으로 그립니다. 기존 `drawBat` 을 복사해 고치는 것이 가장 빠릅니다.

## 9. 브랜치 규칙 (git-flow)

| 브랜치 | 쓰임 |
| --- | --- |
| `main` | 배포용. GitHub Pages 가 이 브랜치를 보여줍니다. 직접 커밋하지 않습니다. |
| `dev` | 개발용. 완성된 기능이 모이는 곳입니다. |
| `feature/<이름>` | 기능 하나를 만드는 곳. `dev` 에서 만들고 `dev` 로 합칩니다. |
| `release/<버전>` | 배포 준비. `dev` 에서 만들고 `main` 과 `dev` 양쪽에 합칩니다. |
| `hotfix/<이름>` | 배포된 것의 급한 수정. `main` 에서 만들고 `main` 과 `dev` 양쪽에 합칩니다. |

**기능 하나를 만드는 순서**

```
git switch dev
git switch -c feature/map
(작업하고 커밋)
git switch dev
git merge --no-ff feature/map
```

**배포하는 순서**

```
git switch -c release/0.1.0 dev
(버전 확인, 마지막 수정)
git switch main
git merge --no-ff release/0.1.0
git tag v0.1.0
git switch dev
git merge --no-ff release/0.1.0
```
