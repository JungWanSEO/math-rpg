# Solve the Tower

수학 선생 친구를 위한 슬더슬 같은 수학게임

수학을 포기했던 주인공이 문제를 풀어 몬스터와 싸우며 수학의 탑을 오르는 스마트폰용 로그라이크 웹 게임입니다. 갈림길 지도에서 길을 골라 보스까지 올라가고, 쓰러지면 처음부터 다시 시작합니다.

이 문서는 사용설명서처럼 위에서부터 순서대로 따라 하면 되도록 썼습니다.

## 2. 실행해 보기

파일을 더블클릭해서 열면 동작하지 않습니다. 브라우저가 보안상 데이터 파일을 읽지 못하게 막기 때문입니다. 아래 둘 중 하나로 실행합니다.

**내 컴퓨터에서**

1. 이 폴더에서 터미널을 엽니다.
2. `python -m http.server 8000` 을 실행합니다. (VS Code의 Live Server 확장도 됩니다.)
3. 브라우저에서 `http://localhost:8000` 을 엽니다.

**스마트폰에서 (GitHub Pages)**

1. 저장소의 Settings → Pages 로 갑니다.
2. Source 를 "Deploy from a branch" 로 두고 브랜치와 `/ (root)` 를 고른 뒤 Save 를 누릅니다.
3. 잠시 뒤 `https://<계정>.github.io/solve-the-tower/` 로 접속합니다.

개발 중에는 `dev` 브랜치를, 정식 배포 뒤에는 `main` 브랜치를 보게 합니다.

**처음부터 다시 해 보고 싶을 때**

진행 기록은 브라우저에 저장됩니다. 브라우저 설정에서 이 사이트의 데이터를 지우면 튜토리얼부터 다시 시작합니다.

튜토리얼은 첫 전투에서 한 번만 나오고, 노란 안내 줄의 "건너뛰기"로 바로 끝낼 수 있습니다.

## 3. 게임 방법

### 처음 화면

- **이어서 하기**: 진행 중인 지도가 있으면 나옵니다. 하던 곳에서 계속합니다.
- **시작하기 / 처음부터 다시**: 범위를 고르고 새 지도에서 출발합니다. 진행 중인 지도가 있으면 한 번 더 눌러야 지워집니다.
- **도감**: 만난 몬스터와 유형별 기록을 봅니다.
- **메뉴**: 게임 중 어느 화면에서나 위쪽 **메뉴** 버튼(또는 스마트폰의 뒤로 버튼, 키보드 Esc)으로 잠시 멈춥니다. **계속하기** 와 **처음 화면으로 나가기** 가 있습니다. 전투 도중에 나가면 그 전투는 처음부터 다시 하고, 체력과 힌트는 그대로 저장됩니다.
게임 중에는 위쪽 **메뉴** 버튼의 "처음 화면으로 나가기"로 언제든 돌아올 수 있습니다.
지도 화면의 "처음 화면" 버튼으로 언제든 돌아올 수 있습니다.

### 범위 고르기

새 지도를 시작할 때마다 이번 판에 나올 문제 유형을 고릅니다.

- 단원 제목 옆의 **모두 고르기 / 모두 빼기** 로 단원을 통째로 넣거나 뺄 수 있습니다.
- 유형마다 정답률과 정복 여부가 보입니다. 부족한 유형만 골라 집중할 수 있습니다.
- **전체**, **미정복만**, **지난번과 같게** 버튼으로 빠르게 고를 수 있습니다.
- 유형을 하나 더 넣을 때마다 전투 골드가 5%씩 늘어납니다. (최대 50%)
- 고른 범위에 어려운 단계의 문제가 없으면 가장 가까운 단계의 문제가 대신 나옵니다.
- 적의 약점 유형도 고른 범위 안에서 정해집니다.

### 지도

1. 지도는 10층입니다. 맨 아래 줄에서 출발할 칸을 고르고, 맨 위의 보스까지 올라갑니다.
2. 선으로 이어진 칸으로만 갈 수 있습니다. 어느 길로 갈지는 직접 정합니다.
3. 5층에는 중간 보스가 있고, 보스 바로 아래 층은 항상 휴식입니다.
4. 지도는 시작할 때마다 새로 만들어집니다.

| 칸 | 무슨 일이 생기나 |
| --- | --- |
| 전투 | 몬스터와 싸웁니다. 이기면 골드를 받고 강화를 하나 고릅니다. |
| 강적 | 체력과 공격이 더 센 몬스터입니다. 골드를 더 줍니다. |
| ? | 무슨 일이 생길지 모릅니다. 아래 표를 봅니다. |
| 보물 | 문제를 맞히면 골드와 힌트를 얻습니다. |
| 상점 | 골드로 강화를 삽니다. |
| 휴식 | 체력을 회복하거나, 틀렸던 유형을 복습해 힌트를 얻습니다. |
| 중간 보스 | 반드시 지나가는 강한 적입니다. |
| 보스 | 응용 문제를 냅니다. 이기면 단원 클리어입니다. |

**? 칸에서 생기는 일** (일곱 가지 중 하나가 무작위로 나옵니다)

| 사건 | 결과 |
| --- | --- |
| 맑은 샘물 | 체력 회복 |
| 측량사의 쪽지 | 힌트 +1 |
| 떨어진 지갑 | 골드 획득 |
| 짙은 안개 | 체력 감소 (1 아래로는 내려가지 않음) |
| 소매치기 | 골드 감소 |
| 수상한 석상 | 도전하면 어려운 문제. 맞히면 강화, 틀리면 체력 감소. 지나칠 수도 있음 |
| 기습 | 전투가 시작됨 |

### 전투

1. 적의 "다음 턴 예고"를 봅니다.
2. 행동을 고릅니다.
   - **기본 공격**: 쉬운 문제가 나옵니다. 맞히면 약한 피해를 줍니다.
   - **스킬**: 어려운 문제가 나옵니다. 맞히면 큰 피해를 줍니다.
   - **방어**: 쉬운 문제가 나옵니다. 맞히면 피해를 받지 않고 반격합니다. 틀리면 피해를 절반 받습니다. 연속으로는 쓸 수 없습니다.
3. 문제가 나오면 답을 고릅니다. 시간 제한은 없습니다.
4. 맞히면 적의 보통 공격을 받지 않습니다. 틀리면 공격이 빗나가고 적의 공격을 받으며, 해설이 나옵니다. 틀린 문제는 정답과 해설이 화면에 남고, **확인했어요, 다음** 을 눌러야 넘어갑니다.
5. 3문제를 연속으로 맞히면 필살기를 쓸 수 있습니다. 틀리면 게이지가 0이 됩니다.
6. 적의 약점 유형 문제를 맞히면 피해가 1.5배입니다.
7. **강한 공격**(3턴마다, 붉은 예고)은 문제를 맞혀도 맞습니다. 방어로만 막을 수 있습니다.
8. 힌트를 쓰면 틀린 보기 하나가 지워집니다.
9. 체력이 0이 되면 게임 오버입니다. 골드와 강화는 사라지고, 새 지도로 처음부터 다시 시작합니다. 도감 기록은 남습니다.

적은 3턴마다 강한 공격을 합니다. 강한 공격은 공격 문제를 맞혀도 피할 수 없고 방어로만 막을 수 있습니다. 예고를 보고 그 턴에 방어하는 것이 요령입니다.

| 삼각비 | 변의 비 | 1 |
| 삼각비 | 삼각비의 상호 관계 | 2, 3 |
| 삼각비 | 변의 길이 | 2 |
| 삼각비와 도형 | 높이 구하기 | 2 |

아직 없는 것: 공간도형 응용, 명제와 조건, 산포도와 상관계수, 가설검정의 생각.

문제는 `data/units/<단원>.json` 에 있습니다. **문장 틀**과 **숫자 묶음**으로 나뉘어 있어서, 숫자만 다른 문제는 한 줄만 추가하면 3개 언어로 모두 나옵니다.

**숫자만 다른 문제 추가**

해당 틀의 `items` 에 한 줄을 더합니다.

```json
{ "d": 20, "deg": 45, "answer": "20 m", "wrong": ["10√2 m", "22 m", "10 m"] }
```

- `answer`: 정답
- `wrong`: 오답 보기 3개. 정답과 겹치면 안 됩니다.
- 나머지(`d`, `deg` 등): 문장 틀의 `{d}`, `{deg}` 자리에 들어갈 값

**새로운 종류의 문제 추가**

`templates` 에 틀을 하나 더합니다.

| 항목 | 뜻 |
| --- | --- |
| `id` | 틀의 이름 (영문, 겹치지 않게) |
| `level` | 1 = 개념 확인, 2 = 계산, 3 = 응용 |
| `type` | 유형. 파일 위쪽 `types` 에 있는 이름이어야 합니다 |
| `text` | 문제 문장. ja, ko, en 세 가지를 모두 씁니다 |
| `explain` | 틀렸을 때 보여줄 해설 한 줄 |
| `items` | 숫자 묶음 목록 |

**숫자를 자동으로 만드는 문제**

틀에 `items` 대신 `"gen": "<이름>"` 을 적으면 `js/generators.js` 의 생성기가 매번 새 숫자를 만듭니다. 오답 보기는 "사인 대신 코사인을 쓴 값"처럼 흔한 실수에서 나오는 값으로 만들어집니다.

새 생성기를 추가할 때는 답이 깔끔하게 떨어지는 숫자만 쓰도록 하고, 정답과 값이 같은 오답이 생기지 않게 `item()` 과 `choose()` 를 그대로 씁니다.

**문제에 그림 붙이기**

틀에 `figure` 를 적으면 그 틀의 모든 문제에 그림이 붙습니다. 숫자는 `items` 에서 자동으로 들어갑니다.

```json
"figure": { "kind": "triangle", "angle": "θ", "opp": "{a}", "adj": "{b}", "hyp": "{c}" }
```

| kind | 그림 | 적을 수 있는 자리 |
| --- | --- | --- |
| `triangle` | 직각삼각형 | `angle` 각, `opp` 맞은편 변, `adj` 이웃 변, `hyp` 빗변 |
| `tower` | 탑 하나 | `angle` 올려본 각, `dist` 수평거리, `height` 높이 |
| `twopoint` | 탑과 두 지점 | `far` 먼 지점의 각, `near` 가까운 지점의 각, `gap` 두 지점 사이, `height` 높이 |
| `anytri` | 삼각형 ABC | `angleA` `angleB` `angleC` 각, `sideA` `sideB` `sideC` 변 (a는 A와 마주 보는 변) |

구해야 하는 자리에는 `"?"` 를 적습니다. 표시하지 않을 자리에는 `""` 를 적습니다.

**어느 단계가 어디에 나오나**

| 단계 | 나오는 곳 |
| --- | --- |
| 1 | 기본 공격, 방어, 휴식의 복습 |
| 2 | 스킬, 보물, ? 칸의 석상, 보스의 기본 공격 |
| 3 | 보스의 스킬 |

**단원 추가하기**

1. `data/units/` 에 단원 파일을 만듭니다. (기존 `math1-trig.json` 을 복사해 고치면 됩니다.)
2. `data/catalog.json` 의 해당 과목 `units` 에 파일 이름을 추가합니다. 과목이 없으면 과목도 추가합니다.
3. 범위 고르기 화면과 도감에 저절로 나타납니다.

단원 파일의 `groups` 는 범위 고르기 화면에서 유형을 묶어 보여주는 소제목입니다.

## 6. 숫자 조정하는 법 (밸런스)

| 고치고 싶은 것 | 파일 |
| --- | --- |
| 체력, 피해량, 적의 공격, 골드 보상, 지도 크기, ? 칸의 수치 | `js/config.js` |
| 몬스터별 체력, 약점, 내는 문제 단계 | `data/monsters.json` |
| 강화의 효과, 상점 가격, 칸이 나올 확률 | `js/run.js` |

각 줄 옆에 뜻이 적혀 있습니다. 지금 값은 모두 임시입니다. 직접 해 보고 고칩니다.

**지금 수치의 기준**

자동으로 플레이하는 봇으로 지도 한 장을 여러 번 돌려 본 결과입니다. 봇은 강한 공격 예고 때만 방어하고 나머지는 아무 공격이나 고릅니다. 사람은 이보다 잘합니다.

| 정답률 | 지도 한 장을 클리어하는 비율 |
| --- | --- |
| 90% | 거의 항상 |
| 75% | 4번 중 3번쯤 |
| 60% | 4번 중 1번쯤 |

## 7. 화면 문구 고치는 법

버튼, 안내 문장은 `lang/ja.json`, `lang/ko.json`, `lang/en.json` 에 있습니다. 세 파일은 같은 항목을 가져야 합니다. 한 파일에 항목을 추가하면 나머지 두 파일에도 추가합니다.

## 8. 몬스터 추가하는 법

1. `data/monsters.json` 에 항목을 추가합니다. (`id`, 이름, 뜻하는 실수, 체력, 약점 유형)
2. `js/stage.js` 에 그리는 함수를 하나 만들고 `FOE_DRAW` 에 같은 `id` 로 등록합니다.

그림은 이미지 파일 없이 원, 다각형, 선으로 그립니다. 기존 `drawBat` 을 복사해 고치는 것이 가장 빠릅니다. `"boss": true` 를 넣으면 지도의 마지막 칸에 나옵니다.

## 9. 브랜치 규칙 (git-flow)

| 브랜치 | 쓰임 |
| --- | --- |
| `main` | 배포용. 정식 공개 뒤 GitHub Pages 가 이 브랜치를 보여줍니다. 직접 커밋하지 않습니다. |
| `dev` | 개발용. 완성된 기능이 모이는 곳입니다. |
| `feature/<이름>` | 기능 하나를 만드는 곳. `dev` 에서 만들고 `dev` 로 합칩니다. |
| `release/<버전>` | 배포 준비. `dev` 에서 만들고 `main` 과 `dev` 양쪽에 합칩니다. |
| `hotfix/<이름>` | 배포된 것의 급한 수정. `main` 에서 만들고 `main` 과 `dev` 양쪽에 합칩니다. |

**기능 하나를 만드는 순서**

```
git switch dev
git switch -c feature/offline
(작업하고 커밋)
git switch dev
git merge --no-ff feature/offline
```

**배포하는 순서**

```
git switch -c release/0.1.0 dev
(버전 확인, 마지막 수정)
git switch main
git merge --no-ff release/0.1.0
git tag v0.1.0
git switch dev
git merge --no-ff release/0.1.0
```
